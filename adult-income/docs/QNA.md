# 8단계: Q&A

## 데이터

**Q. 왜 이 데이터셋을 골랐나요?**
처음에는 타이타닉 계열 합성 데이터(10만 행)를 썼습니다. 그런데 분석해 보니 `survived`가 `survival_probability` 열을 확률로 써서 무작위로 뽑은 값이었고, 그래서 어떤 모델을 써도 정확도 상한이 0.77이었습니다. 목표인 0.85가 수학적으로 불가능해서, 0.85 이상이 현실적으로 가능하고 의미 있는 주제인 Adult Income으로 바꿨습니다.

**Q. fnlwgt와 education은 왜 뺐나요?**
- fnlwgt는 이 사람이 미국 인구 몇 명을 대표하는지 나타내는 통계용 가중치입니다. 개인 특성이 아니고, 소득과의 상관계수가 −0.01입니다.
- education은 education_num과 1:1로 대응해서(Bachelors는 항상 13) 같은 정보가 중복됩니다.

**Q. 결측치를 왜 지우지 않았나요?**
결측이 있는 행이 7.4%라 지우면 데이터 손실이 큽니다. 또 workclass가 비어 있는 사람의 고소득 비율은 10%로, 평균 25%와 크게 다릅니다. 비어 있다는 것 자체가 정보라서 `Unknown` 범주로 남겼습니다.

**Q. race, sex를 모델에 넣어도 되나요?**
예측 성능에는 도움이 되지만, 실제 서비스(채용, 대출 등)에 쓰면 차별 문제가 생길 수 있습니다. 이번 과제는 학습 목적이라 포함했고, 빼고 비교하는 것을 다음 개선 후보로 남겼습니다.

## 모델

**Q. 왜 HistGradientBoosting인가요?**
같은 데이터로 비교했을 때 로지스틱 회귀 0.847, 랜덤포레스트 0.848, HistGradientBoosting 0.873으로 가장 좋았습니다. 표 형태의 데이터에서 일반적으로 강하고, sklearn에 내장돼 있어 추가 설치도 필요 없습니다.

**Q. 정확도가 0.873에서 0.862로 떨어졌는데 왜 개선인가요?**
정확도만 보면 실제 고소득자의 35%를 놓치는 문제가 가려집니다. 데이터의 76%가 저소득이라서, 전부 저소득으로 찍어도 정확도가 0.76이 나옵니다. 임계값을 조정해 정확도는 1%p 내주고, 고소득자 재현율을 0.65에서 0.76으로 올렸습니다. F1도 0.708에서 0.723으로 올랐고, 정확도는 여전히 목표 0.85 이상입니다.

**Q. 임계값 0.37은 어떻게 정했나요? test에 맞춘 것 아닌가요?**
아닙니다. train 데이터의 20%를 검증용으로 떼서, 그 안에서 F1이 가장 높은 값을 골랐습니다. test 데이터는 최종 평가에만 한 번 썼습니다.

**Q. 하이퍼파라미터 튜닝은 안 했나요?**
5가지 조합을 해봤지만 검증 정확도 차이가 0.002 이내였습니다. 효과가 거의 없어서 기본값을 유지했습니다.

**Q. 정확도를 더 올릴 수는 없나요?**
이 데이터에서 알려진 최고 성능도 0.87~0.88 수준입니다. 지금 모델이 거의 상한에 가깝고, 더 올리려면 새로운 정보(피처)가 필요합니다.

## API / 화면

**Q. 전처리된 CSV를 왜 안 쓰고 Pipeline으로 바꿨나요?**
전처리된 CSV는 원-핫 인코딩된 52개 열이라, API가 이 형태로 입력을 받으면 사용자가 쓸 수 없습니다. 전처리를 `src/features.py` 한 곳에 두고 원-핫 인코딩을 Pipeline 안에 넣었습니다. 그래서 학습과 예측이 항상 같은 전처리를 거치고, API는 "나이 39, 학사" 같은 원래 값을 그대로 받습니다.

**Q. 이상한 값을 넣으면 어떻게 되나요?**
FastAPI(pydantic)가 자동으로 검사해서 422 에러를 돌려줍니다. 나이 17~90, 학력 1~16, 근무시간 1~99 범위를 벗어나거나, 없는 범주를 넣거나, 필수값이 빠지면 거부되고, 화면에는 어떤 값이 잘못됐는지 표시됩니다.

**Q. 미국 외 국가를 넣으면요?**
학습 때 미국 외 국가를 전부 `Other`로 묶었기 때문에, API도 어떤 국가명이든 `Other`로 처리합니다.

**Q. 모델 파일(model.joblib)은 왜 커밋하지 않았나요?**
sklearn 버전이 다르면 저장된 모델을 불러올 때 경고나 오류가 날 수 있습니다. 학습이 몇 초면 끝나서, 각자 `python -m src.train`으로 만드는 게 더 안전합니다.

## 검증

**Q. 예상대로 나오는지 어떻게 확인했나요?**
`python -m scripts.validate`로 네 가지를 확인합니다.
1. test 정확도가 0.85 이상인지 (결과 0.862)
2. 학습할 때 기록한 지표와 같은지 (모델이 제대로 저장되고 불러와졌는지)
3. 확률이 0~1 범위인지
4. 대표 사례가 상식대로 나오는지
   - 고학력·관리직·기혼은 >50K (99.8%)
   - 22세·고졸·파트타임은 <=50K (0.2%)
   - 결측값이 있어도 정상 처리

`--api` 옵션을 주면, 실행 중인 API 응답이 모델 직접 호출과 같은지도 20건으로 확인합니다.
